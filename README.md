# 馆际作品借展

处理复合作品信息、借展约束、状态交接与策展引用。

`fixtures/domain.json` 保存首批领域名词和状态样例，便于接口联调时保持一致语义。运行 `python3 service.py --check` 可检查基础配置；执行 `npm test` 可验证健康入口与全部领域契约。

## 模型分层

- `domain.py` — 领域核心（仅标准库）：
  - `Work` / `Segment` / `Contribution`：作品实体、组成区段、作者贡献（合作顺序、题跋等挂到具体区段）；
  - `Agreement`：展期、展厅、照度、运输、保险、数字传播用途；改期通过版本链（`supersedes`）保留旧条款；
  - `Handover` / `ConditionReport` / `Incident`：出库、到馆、布展、撤展、归还五类交接，双方签认；
  - `Claim` / `ClaimSubmission` / `ClaimDecision` / `FundEntry`：损伤理赔案、角色化补充材料版本、理赔决定与资金分录；
  - `LabelVersion`：展签版本，发布即锁定证据快照。
- `service.py` — HTTP 编解码与状态码映射，规则全部委托给 `domain.py`。
- `domain_contract.py` / `claim_contract.py` — 业务规则的可执行契约（借展 21 用例 + 理赔 18 用例）。

## 关键规则

1. **复合作品结构**：普通藏品表的一行作品之外，区段（引首/画心/尾纸题跋）与作者贡献（作画/题跋/书引首/鉴藏印/题签，含合作顺序）分别登记；贡献必须指向已登记的区段，合作顺序不得重复。
2. **协议约束**：展期起止、展厅、照度上限（勒克斯）、运输方式、保险（如钉到钉）、数字传播用途随协议保存；跨馆改期生成新版本并保留旧版，当前授权永远取最新版。
3. **交接签认**：五类交接按固定生命周期顺序办理，交出方与接收方角色固定（如出库 = 出借馆 → 运输方），缺签认人或角色不符一律拒绝。
4. **重复扫码幂等**：扫码标识全局唯一；重复扫码返回 `409` 且不产生第二条记录，被拒绝的扫码不会被消费。
5. **损伤冻结**：状态报告记为“损伤”时立即冻结该作品的全部后续交接，登记损伤事件并保全损伤前/后图像哈希（sha256）；须凭书面复核结论解除后，交接链才能继续。
6. **展签快照**：发布日期确认后锁定证据快照（作品、区段、十六位作者贡献、当时协议版本、交接记录、保管状态、未解除风险）；之后的学术更正或改期只产生新版展签，旧版展签与其快照永不改变。
7. **争议追溯**：`/works/{id}/segments/{sid}` 从争议区段直达实体、该区段上的作者贡献、当前保管责任与相关损伤事件；`/works/{id}/risk` 汇总保管、授权范围与未解除风险。
8. **报案锁定**：理赔报案锁定事故发生时有效的保险条款、交接双方签认与图像摘要（取自损伤事件登记时的协议版本）；之后跨馆改期只产生新协议版本，不改变本案保障范围。
9. **角色化追加**：保险方/出借馆/承借馆/运输方只能按自身角色追加估损、异议、修复方案、责任意见（异议向四方开放）；每次追加形成新版本，被理赔决定引用的版本永不替换。
10. **资金守恒**：部分认可与免赔额随理赔决定入账，分期赔付与追偿逐笔追加；赔付累计不超过认可减免赔，追偿累计不超过已赔付；回执唯一、决定唯一，重复回执或并发决定不得多记赔款。
11. **关闭与解冻分离**：理赔关闭要求赔付结清；作品解冻要求出借馆修复复核通过且当前保管方确认保管责任，两者分别判断、互不为前提。未获授权的机构看不到作品敏感材料（图像摘要、材料与分录）。

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/health` | 服务身份健康检查 |
| POST | `/works` | 登记作品（可含区段与贡献） |
| GET | `/works/{id}` | 作品视图（结构、当前协议、保管状态、冻结标记） |
| GET | `/works/{id}/risk` | 开放损伤、理赔阶段、缺少的签认与资金变化（`?viewer_org=` 未授权脱敏） |
| GET | `/works/{id}/segments/{sid}` | 局部状态争议定位 |
| POST | `/agreements` | 订立借展协议 |
| POST | `/agreements/{id}/reschedule` | 跨馆改期/改条款，生成新版本 |
| POST | `/handovers` | 办理一次双方签认交接 |
| POST | `/incidents/{id}/resolve` | 损伤复核解除、恢复交接（已报案的须先满足解冻双条件） |
| POST | `/claims` | 理赔报案：锁定事故时保险条款、双方签认与图像摘要 |
| GET | `/claims/{id}` | 理赔案视图（`?viewer_org=` 未授权机构自动隐去敏感材料） |
| POST | `/claims/{id}/submissions` | 按角色追加估损/异议/修复方案/责任意见（各成新版本） |
| POST | `/claims/{id}/decide` | 保险方理赔决定：部分认可+免赔额，引用材料版本，仅生效一次 |
| POST | `/claims/{id}/entries` | 追加赔付/追偿分录（回执幂等、金额守恒） |
| POST | `/claims/{id}/restoration-review` | 出借馆修复复核（解冻前提之一） |
| POST | `/claims/{id}/custody-ack` | 当前保管方确认保管责任（解冻前提之二） |
| POST | `/claims/{id}/close` | 关闭理赔（须赔付结清，与作品解冻分别判断） |
| POST | `/works/{id}/labels` | 起草展签 |
| POST | `/works/{id}/labels/publish` | 确认发布日期并锁定快照 |
| POST | `/works/{id}/labels/correct` | 学术更正，另起新版 |
| GET | `/works/{id}/labels` / `.../labels/{v}` | 读取最新版或指定旧版展签 |

规则违反返回 `400`（数据不合法）或 `409`（重复扫码、跳步交接、已冻结、已锁定等状态冲突），响应体为 `{"error": "..."}`。

## 本地运行

```bash
python3 service.py --check      # 自检
npm test                        # service_contract + domain_contract
python3 -m compileall -q .      # 编译检查
python3 service.py --port 8000  # 启动 HTTP 服务
```
