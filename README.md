# 馆际作品借展

处理复合作品信息、借展约束、状态交接与策展引用。

`fixtures/domain.json` 保存首批领域名词和状态样例，便于接口联调时保持一致语义。运行 `python3 service.py --check` 可检查基础配置；执行 `npm test` 可验证健康入口与全部领域契约。

## 模型分层

- `domain.py` — 领域核心（仅标准库）：
  - `Work` / `Segment` / `Contribution`：作品实体、组成区段、作者贡献（合作顺序、题跋等挂到具体区段）；
  - `Agreement`：展期、展厅、照度、运输、保险、数字传播用途；改期通过版本链（`supersedes`）保留旧条款；
  - `Handover` / `ConditionReport` / `Incident`：出库、到馆、布展、撤展、归还五类交接，双方签认；
  - `Claim` / `ClaimAddition` / `FundEntry`：理赔报案基线、四方按角色追加的材料版本、守恒的资金分录；
  - `LabelVersion`：展签版本，发布即锁定证据快照。
- `service.py` — HTTP 编解码与状态码映射，规则全部委托给 `domain.py`；查看机构经 `X-Viewer-Org`（中文机构名须百分号编码）声明，用于敏感材料脱敏。
- `domain_contract.py` — 业务规则的可执行契约（51 个用例）。

## 关键规则

1. **复合作品结构**：普通藏品表的一行作品之外，区段（引首/画心/尾纸题跋）与作者贡献（作画/题跋/书引首/鉴藏印/题签，含合作顺序）分别登记；贡献必须指向已登记的区段，合作顺序不得重复。
2. **协议约束**：展期起止、展厅、照度上限（勒克斯）、运输方式、保险（如钉到钉）、数字传播用途随协议保存；跨馆改期生成新版本并保留旧版，当前授权永远取最新版。
3. **交接签认**：五类交接按固定生命周期顺序办理，交出方与接收方角色固定（如出库 = 出借馆 → 运输方），缺签认人或角色不符一律拒绝。
4. **重复扫码幂等**：扫码标识全局唯一；重复扫码返回 `409` 且不产生第二条记录，被拒绝的扫码不会被消费。
5. **损伤冻结**：状态报告记为“损伤”时立即冻结该作品的全部后续交接，登记损伤事件并保全损伤前/后图像哈希（sha256）；冻结不因修复完成或理赔关闭自动解除。
6. **展签快照**：发布日期确认后锁定证据快照（作品、区段、十六位作者贡献、当时协议版本、交接记录、保管状态、未解除风险）；之后的学术更正或改期只产生新版展签，旧版展签与其快照永不改变。
7. **争议追溯**：`/works/{id}/segments/{sid}` 从争议区段直达实体、该区段上的作者贡献、当前保管责任与相关损伤事件；`/works/{id}/risk` 汇总保管、授权范围与未解除风险。
8. **报案基线锁定**：`POST /incidents/{id}/claim` 锁定**事故交接发生时已存在的最新一版协议**（含钉到钉保险条款，自出库起运即附着，不按展期日期判断）、交接双方签认与图像摘要（前/后/交接照哈希）。报案后协议改期或另订新版（如出借馆事后拿新协议、运输方另引一版照片）只产生新材料，**不改变基线与原保障范围**。
9. **四方按角色追加**：保险方只能加估损与核赔结论，承借馆只能加修复方案，运输方只能加责任意见，异议四方皆可；提交机构必须与报案登记的角色机构一致。材料只追加并逐版编号（`seq`），可用 `supersedes_seq` 声明取代本方旧版，但旧版与已被决定引用的证据保留可查、不得替换；理赔关闭后只可另案处理。
10. **资金守恒**：核赔结论（全额认可/部分认可/拒赔）是唯一资金决定且只能作一次；免赔额随结论作为负向分录落账。赔付支持分期（`installment_no`），追偿冲减净额；回执号全局幂等，重复回执、重复分期、并发的第二个决定一律 `409`，累计赔付不得超过认可金额、追偿不得超过已赔未冲减部分，认可款未付清不得关闭。
11. **关闭与解冻分离（双闸门）**：理赔关闭只代表账务/责任了结，不解冻作品。恢复后续交接须同时满足：① 修复复核——先有承借馆修复方案，再由出借馆与承借馆双馆书面签认；② 保管责任——由**当前实际保管方**（按交接链推导，如到馆后是承借馆）签认作品现状并接管。承借馆不能在修复完成后直接解冻。
12. **风险四要素并列**：`/works/{id}/risk` 对每个未结损伤并列呈现开放损伤（含图像）、理赔阶段、`missing_signatures`（修复方案/双馆复核/保管签认/核赔结论/剩余分期）与资金分录变化及汇总；理赔阶段与缺签认清单即使对未授权机构也可见。
13. **授权隔离**：`X-Viewer-Org` 不是报案登记的保险方/出借馆/承借馆/运输方时，理赔视图与风险视图中的协议条款明细、图像摘要、损伤细节、修复材料摘要一律脱敏（`redacted: true`），参与方名单只露保险方；阶段、闸门、缺签认等状态信息仍可见以维持协作。

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/health` | 服务身份健康检查 |
| POST | `/works` | 登记作品（可含区段与贡献） |
| GET | `/works/{id}` | 作品视图（结构、当前协议、保管状态、冻结标记） |
| GET | `/works/{id}/risk` | 当前保管责任、授权范围、未解除风险 |
| GET | `/works/{id}/segments/{sid}` | 局部状态争议定位 |
| POST | `/agreements` | 订立借展协议 |
| POST | `/agreements/{id}/reschedule` | 跨馆改期/改条款，生成新版本 |
| POST | `/handovers` | 办理一次双方签认交接 |
| POST | `/incidents/{id}/claim` | 报案：锁定事故时保险条款、签认与图像摘要 |
| GET | `/incidents/{id}` | 损伤事件与双闸门状态 |
| POST | `/incidents/{id}/restoration-review` | 修复复核（出借馆+承借馆双签） |
| POST | `/incidents/{id}/custody-confirmation` | 当前保管方签认保管责任 |
| POST | `/claims/{id}/additions` | 按角色追加估损/核赔结论/异议/修复方案/责任意见 |
| POST | `/claims/{id}/fund-entries` | 追加赔付（可分期）/追偿分录，回执幂等 |
| POST | `/claims/{id}/close` | 保险方关闭理赔（不解冻） |
| GET | `/claims/{id}` | 理赔视图（基线、材料版本、资金分录、双闸门；按 `X-Viewer-Org` 脱敏） |
| POST | `/works/{id}/labels` | 起草展签 |
| POST | `/works/{id}/labels/publish` | 确认发布日期并锁定快照 |
| POST | `/works/{id}/labels/correct` | 学术更正，另起新版 |
| GET | `/works/{id}/labels` / `.../labels/{v}` | 读取最新版或指定旧版展签 |

规则违反返回 `400`（数据不合法）或 `409`（重复扫码、跳步交接、已冻结、已锁定等状态冲突），响应体为 `{"error": "..."}`。

## 本地运行

```bash
python3 service.py --check      # 自检
npm test                        # service_contract + domain_contract
python3 -m compileall -q .      # 编译检查
python3 service.py --port 8000  # 启动 HTTP 服务
```
